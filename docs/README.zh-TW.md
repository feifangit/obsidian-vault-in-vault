# Vault in Vault

把私人筆記和圖片加密儲存在 Obsidian Vault 中，只在需要時解鎖。

Vault in Vault 可以幫助你：

- **保護靜態檔案內容。** 加密日記、個人資料、工作筆記和圖片，避免它們在 Vault 副本、備份或同步目錄中保持可讀。
- **保留原本的檔案位置。** 鎖定後的檔案仍在原目錄中，並儲存為標準的密碼加密 `.age` 檔案。
- **解鎖後正常使用 Obsidian。** 點選受保護檔案並輸入密碼，即可繼續使用原生編輯器、圖片預覽、連結和搜尋。
- **不離開 Obsidian 就能重新鎖定。** 最後一個分頁關閉時加密目前檔案、隨時鎖定全部暴露的明文，或在 Vault 閒置一段時間後自動鎖定。
- **決定哪些內容需要保護。** 透過 Vault 層級的 `.ageconfig` 設定副檔名，並排除公開目錄、範本或個別檔案。
- **使用熟悉的介面語言。** 外掛會跟隨 Obsidian，目前支援英文、簡體中文、繁體中文、日文和韓文。

Vault in Vault 會保護檔案內容，但不會隱藏檔名和目錄結構。

> [!WARNING]
> 檔案解鎖期間，明文會實際寫入磁碟。請先備份，並在用於重要資料前了解下方的安全界線。本專案尚未經過獨立安全稽核。

## 從 Obsidian 社群外掛安裝

1. 在 Obsidian 中開啟 **設定 → 第三方外掛**。
2. 選擇 **瀏覽**，搜尋 **Vault in Vault**。
3. 開啟外掛頁面，依序選擇 **安裝**和**啟用**。

Vault in Vault 目前只支援桌面版。你也可以查看它的 [Obsidian Community 頁面](https://community.obsidian.md/plugins/vault-in-vault)。

## 快速了解使用方式

### 加密檔案仍留在原目錄

加密檔案會在檔案總管中顯示 **AGE** 標記。檔名和目錄結構仍然可見，但沒有密碼便無法讀取內容。

![Obsidian 檔案總管中帶有 AGE 標記的加密檔案](images/encrypted-files.png)

### 點選加密檔案即可開啟

需要閱讀或編輯時，點選**解密並開啟**。

![加密 Markdown 檔案的解密並開啟按鈕](images/decrypt-and-open.png)

輸入密碼後即可解密。可以選擇只在目前 Obsidian 工作階段的記憶體中記住密碼；密碼不會寫入磁碟。

![帶有目前工作階段記住密碼選項的密碼視窗](images/password-prompt.png)

解密完成後，筆記會進入 Obsidian 原生編輯器。檔案解鎖期間，Markdown、圖片預覽、連結、搜尋和相容的第三方外掛都可以正常運作。

### 關閉分頁時決定是否重新加密

關閉最後一個仍開啟的受保護明文分頁時，可以只加密剛關閉的檔案、加密所有符合條件的明文檔案，或暫時保留明文。只要還有其他受保護明文分頁開啟，關閉其中一個不會中斷編輯。

![關閉分頁後選擇加密目前檔案或全部檔案](images/encrypt-on-close.png)

### 選擇要保護的檔案類型

設定頁面會顯示 Vault 批次鎖定涵蓋的副檔名。設定預設可見，但修改前必須驗證密碼，以避免誤操作。

![受保護檔案類型和圖片自動解密設定](images/protected-file-settings.png)

### 排除不需要加密的檔案和目錄

如果公開目錄、範本或某個檔案永遠不應參與加密和密碼驗證掃描，可以在 `.ageconfig` 的 `exclude` 中填寫相對於 Vault 根目錄的路徑。填寫目錄會排除其整個子目錄。使用共享策略時，設定頁會以唯讀方式顯示目前的排除項目。

![由 ageconfig 共享策略管理的排除檔案和目錄](images/excluded-paths.png)

### 限制密碼在記憶體中的可用時間

**工作階段安全性**提供兩個互斥選項。**自動清除密碼**只會在固定時間後清除快取密碼；**Vault 閒置後自動鎖定**會等待 Vault 一段時間沒有操作，儲存開啟的 Markdown 編輯器，加密符合條件的明文，關閉已成功保護的分頁，最後清除密碼。

![密碼自動清除和 Vault 閒置自動鎖定設定](images/session-security.png)

Ribbon 圖示會分別表示設定模式和密碼狀態：

![手動鎖定、密碼自動清除、閒置自動鎖定和密碼狀態燈圖例](images/security-mode-icons.png)

## 主要功能

- 從檔案總管直接開啟使用密碼加密的 `.age` 檔案。
- 解密 Markdown 和圖片並將明文寫回原目錄，保留原生編輯、預覽、連結、搜尋和第三方外掛功能。
- 關閉最後一個受保護明文分頁後，可選擇加密剛關閉的檔案、加密全部符合條件的明文，或暫時保留明文。
- 提供**立即加密並鎖定 Vault** 命令和 Ribbon 鎖定按鈕。
- 使用者明確選擇後，密碼只會快取在目前外掛工作階段的記憶體中。
- Ribbon 鎖定按鈕下方以紅、綠、黃狀態燈表示密碼不可用、已快取或計時器即將到期。
- 可以在固定時間後只清除快取密碼，也可以在目前 Vault 長時間沒有操作後自動加密並鎖定。
- 預設保護 `.md`、`.avif`、`.bmp`、`.gif`、`.jpeg`、`.jpg`、`.png`、`.svg` 和 `.webp`，也可以設定要略過的檔案或資料夾。
- 保留子目錄，排除 Vault 設定目錄和已經以 `.age` 結尾的檔案。
- 刪除來源檔案前，會重新讀取並驗證剛產生的明文或密文。
- 跟隨 Obsidian 的介面語言，支援英文、簡體中文、繁體中文、日文和韓文。

## 檔案流程

開啟 `notes/private.md.age` 並選擇**解密並開啟**：

```text
notes/private.md.age
    -> 解密並驗證 notes/private.md
    -> 刪除 notes/private.md.age
    -> 使用原生編輯器開啟 notes/private.md
```

關閉最後一個仍開啟的受保護明文分頁時，對話框會提供預設收合的待加密檔案清單；如果 `.ageconfig` 設定了排除路徑，還會用另一個預設收合的清單列出不會加密的檔案和資料夾。接著可以選擇：

- **加密此檔案**：只加密剛關閉的檔案；
- **全部加密（N）**：加密所有符合條件的明文檔案；
- **保留明文**：本次保留明文。

分頁會先關閉，讓 Obsidian 完成正常儲存，然後在應用程式仍執行時進行加密。取消密碼輸入、加密期間檔案發生變更或驗證失敗時，外掛都會保留明文來源檔案。

選擇**全部加密**或執行**立即加密並鎖定 Vault**後，外掛會主動清除目前工作階段快取的密碼；這並不是 Obsidian 工作階段自然結束。之後再開啟加密檔案會重新詢問密碼。只加密剛關閉的單一檔案時，不會主動清除快取。

外掛不會依賴應用程式退出掛鉤進行互動式加密，因為 Obsidian 不會可靠地等待非同步加密完成。退出前請先關閉受保護的分頁，或執行**立即加密並鎖定 Vault**。

## 密碼規則

- Vault 中存在未被排除的 `.age` 檔案時，會使用其中容量最小的檔案驗證密碼。
- 尚無 `.age` 檔案時，首次加密要求輸入兩次密碼。
- 選擇記住密碼後，密碼只存在於目前外掛工作階段的 JavaScript 記憶體中。
- 密碼不會寫入 `data.json`。
- 不提供密碼復原；密碼遺失後無法復原密文。

### 工作階段安全計時器

設定頁提供兩個互斥的計時器，預設都為**關閉**：

- **自動清除密碼**：從密碼進入記憶體時開始固定計時。使用者操作不會延長時間；到期只清除密碼，不關閉分頁，也不改變仍為明文的檔案。
- **Vault 閒置後自動鎖定**：目前 Vault 中發生鍵盤、滑鼠、觸控、捲動、編輯或分頁切換時會重新計時。到期後，外掛會先等待 Markdown 編輯器儲存，再加密所有符合條件且未被排除的明文，關閉已成功保護的分頁，並清除密碼，不再顯示確認對話框。

Ribbon 使用「鑰匙＋小時鐘」表示密碼自動清除，使用「鎖＋環形箭頭」表示自動閒置鎖定；兩個計時器都關閉時顯示一般鎖。右上角徽章只表示設定模式，底部紅、綠、黃狀態燈分別表示密碼不可用、可用和期限即將到期。設定頁使用相同圖示。

自動閒置鎖定必須把密碼保留在記憶體中，因此啟用後密碼視窗會固定開啟**記住密碼直到自動鎖定**。Obsidian 重新啟動後絕不會復原密碼；在使用者再次輸入密碼前，自動鎖定不會進入待命狀態。

此處的閒置只表示外掛沒有在這個 Vault 的 Obsidian 主視窗或彈出視窗中觀察到操作，不是作業系統層級的閒置偵測。切換到其他應用程式後會繼續計時；背景同步和檔案修改時間不會重設計時。電腦休眠或 Obsidian 暫停時，恢復後會立即重新檢查期限。

## 加密範圍設定和 `.ageconfig`

檔案類型選項位於**設定 → Vault in Vault → 受保護的檔案類型**，安全計時器也在同一個設定頁面。沒有 `.ageconfig` 時，副檔名、排除路徑和計時器設定會儲存在目前 Vault 外掛目錄的 `data.json` 中；密碼絕不會寫入其中。驗證 Vault 密碼後才能編輯保護策略，計時器則隨時可以調整。

如果希望 Obsidian 外掛和 Go 命令列工具共用同一套策略，可以在 Vault 根目錄建立 `.ageconfig`：

```json
{
  "extensions": [".md", ".png", ".jpg"],
  "exclude": ["Public", "Templates/daily.md", "attachments/shared"]
}
```

- `extensions` 決定哪些明文類型需要保護；可以省略，省略時使用內建的 Markdown 和常見圖片預設類型。明確提供時不能是空陣列。
- `exclude` 可以填寫相對於 Vault 根目錄的單一檔案或目錄；目錄下的全部內容都會略過。
- 路徑區分大小寫，不支援 `*`、`?` 等萬用字元，也不能使用絕對路徑或 `..`。
- `.ageconfig` 存在時優先於 `data.json`。設定頁會顯示策略來源，並將共享的副檔名和排除項目顯示為唯讀；可以用設定頁按鈕在系統預設編輯器中開啟，或在 Finder／檔案管理員中顯示。儲存後點選**重新載入 .ageconfig**。
- 設定無效時，外掛會阻止加密，不會默默退回較寬泛的預設策略。`.ageconfig` 和 `data.json` 都不會儲存密碼。

如果只想設定排除路徑，可以這樣寫：

```json
{
  "exclude": ["Public", "Templates"]
}
```

## 安全界線

- 解鎖後的內容是磁碟上的一般明文檔案。
- Metadata cache、搜尋索引、File Recovery、第三方外掛、同步工具和系統備份可能保留明文。
- 當機、強制結束、斷電或直接退出應用程式可能留下明文。
- JavaScript 無法保證密碼字串會立即從程序記憶體中清除。
- 外掛只會在建立、重新讀取並驗證替代檔案之後刪除來源檔案。將來源明文移到垃圾桶會留下未加密副本，因此加密切換不會使用 Obsidian 的一般垃圾桶行為。
- 檔案解鎖期間，外掛無法防禦能夠讀取 Obsidian 程序或本機檔案的其他軟體和使用者。

外掛沒有遙測、廣告、帳號要求或遠端服務，也不會存取目前 Vault 以外的檔案。一般使用完全離線。

## 本機安裝

安裝本機開發版本需要 Node.js 20 或更新版本：

```bash
npm ci
npm run check
npm run install:vault -- "/你的/Vault/絕對路徑"
```

最後一個命令會把 `main.js`、`manifest.json` 和 `styles.css` 複製到：

```text
<Vault>/.obsidian/plugins/vault-in-vault/
```

也可以手動複製這三個檔案。接著重新啟動或重新載入 Obsidian，並在**設定 → 第三方外掛**中啟用 **Vault in Vault**。

如果安裝過 ID 為 `fileencrypt-age-viewer` 的早期開發版本，請先停用舊版。新版 ID 是 `vault-in-vault`，Obsidian 會將它們識別為兩個外掛。若要保留副檔名設定，可以把舊目錄的 `data.json` 複製到新目錄；其中不包含密碼。

## 開發和發布

```bash
npm ci
npm run dev
npm test
npm run check
```

使用 `npm version patch`、`npm version minor` 或 `npm version major` 更新版本。腳本會同步 `package.json`、`manifest.json` 和 `versions.json`。推送不含 `v` 前綴、與 manifest 版本完全一致的標籤後，GitHub Actions 會建置並產生草稿 Release。這就是一般的 **Create a release** 步驟，不需要再手動建立第二個 Release。

開啟草稿、填寫 release notes，並確認 `main.js`、`manifest.json` 和 `styles.css` 是三個可單獨下載的附件，然後點選 **Publish release**。草稿狀態無法由 Obsidian 安裝，也不能用於 Community 提交。

## 相容性

Vault in Vault 0.8.0 及後續版本需要 Obsidian 1.8.7 或更新版本，讓外掛可以跟隨 Obsidian 目前選擇的介面語言。
