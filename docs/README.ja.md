# Vault in Vault

Obsidian の保管庫内にあるプライベートなノートや画像を暗号化し、必要なときだけロックを解除します。

Vault in Vault でできること：

- **保存中の機密データを保護。** 日記、個人情報、仕事のノート、画像を暗号化し、コピー、バックアップ、同期された保管庫で内容がそのまま読まれるのを防ぎます。
- **元のファイル配置を維持。** ロックされたファイルは元のフォルダーに残り、標準のパスワード暗号化された `.age` ファイルとして保存されます。
- **ロック解除中は Obsidian を通常どおり使用。** 保護されたファイルを開いてパスワードを入力すれば、標準エディター、画像プレビュー、リンク、検索を利用できます。
- **Obsidian 内から平文を再ロック。** 最後のタブを閉じたときに 1 ファイルを暗号化したり、公開中のすべてのファイルを手動または保管庫のアイドル後にロックしたりできます。
- **保護対象を選択。** 保管庫全体の `.ageconfig` ポリシーで拡張子を指定し、公開フォルダー、テンプレート、個別ファイルを除外できます。
- **使い慣れた言語で操作。** インターフェースは Obsidian の言語設定に従い、現在は英語、簡体字中国語、繁体字中国語、日本語、韓国語に対応しています。

Vault in Vault が保護するのはファイルの内容です。ファイル名とフォルダー構造は表示されたままです。

> [!WARNING]
> ファイルのロック解除中は平文がディスクに書き込まれます。重要なデータに使用する前にバックアップを取り、[セキュリティモデル](#セキュリティモデル)を確認してください。このプロジェクトは独立したセキュリティ監査を受けていません。

## Obsidian コミュニティプラグインからインストール

1. Obsidian で**設定 → コミュニティプラグイン**を開きます。
2. **閲覧**を選択し、**Vault in Vault** を検索します。
3. プラグインを選択し、**インストール**、**有効化**の順に選択します。

Vault in Vault は現在デスクトップ版だけに対応しています。[Obsidian Community の掲載ページ](https://community.obsidian.md/plugins/vault-in-vault)も確認できます。

## クイックツアー

### 暗号化されたファイルは元のフォルダーに残ります

暗号化されたファイルには、ファイルエクスプローラーで **AGE** と表示されます。ファイル名とフォルダー構造は確認できますが、パスワードなしでは内容を読めません。

![Obsidian のファイルエクスプローラーで AGE と表示された暗号化ファイル](images/encrypted-files.png)

### ロックされたファイルをクリックして開きます

ファイルを読み取る、または編集するときは、**復号して開く**を選択します。

![暗号化された Markdown ファイルの復号して開く操作](images/decrypt-and-open.png)

パスワードを入力します。必要に応じて、現在の Obsidian セッション中だけメモリに記憶できます。パスワードがディスクに保存されることはありません。

![セッション中にパスワードを記憶するオプションがある入力画面](images/password-prompt.png)

復号後、ノートは Obsidian の標準エディターで開きます。ロック解除中は Markdown、画像プレビュー、リンク、検索、対応する他のプラグインを通常どおり利用できます。

### タブを閉じるときに暗号化する内容を選びます

保護対象の平文ファイルを開いている最後のタブを閉じると、そのファイルだけを暗号化するか、条件に一致するすべての平文ファイルを暗号化するか、平文のままにするかを選択できます。他の保護対象の平文タブが開いている間は、1 つのタブを閉じても作業は中断されません。

![タブを閉じた後に 1 ファイルまたはすべてのファイルを暗号化する確認画面](images/encrypt-on-close.png)

### 保護するファイル形式を選びます

設定ページには、保管庫全体のロック対象となる拡張子が表示されます。設定は常に確認できますが、誤操作を防ぐため、変更にはパスワードの確認が必要です。

![保護対象のファイル形式と埋め込み画像の設定](images/protected-file-settings.png)

### 暗号化しないファイルとフォルダーを指定します

公開フォルダー、テンプレート、個別ファイルを暗号化やパスワード確認のスキャン対象にしたくない場合は、`.ageconfig` の `exclude` に保管庫ルートからの相対パスを追加します。フォルダーを指定すると、その配下全体が除外されます。共有ポリシーの使用中は、現在の除外対象が設定ページに読み取り専用で表示されます。

![ageconfig の共有ポリシーで管理される除外ファイルとフォルダー](images/excluded-paths.png)

### パスワードを利用できる時間を制限します

**セッションのセキュリティ**には、同時に使用できない 2 つの選択肢があります。**パスワードの自動消去**は一定時間後にキャッシュだけを消去します。**保管庫の操作がないときに自動ロック**は操作がない状態を待ち、開いている Markdown エディターを保存し、条件に一致する平文ファイルを暗号化して、保護に成功したタブを閉じ、最後にパスワードを消去します。

![パスワードの自動消去と保管庫の自動アイドルロック設定](images/session-security.png)

リボンアイコンは、設定中のモードとパスワード状態を別々に示します。

![手動ロック、パスワード自動消去、自動アイドルロック、パスワード状態の表示](images/security-mode-icons.png)

## 主な機能

- ファイルエクスプローラーから、パスワードで暗号化された `.age` ファイルを直接開きます。
- Markdown と画像を復号して平文を元のフォルダーに戻し、標準の編集、プレビュー、リンク、検索、他のプラグインを利用できます。
- 保護対象の平文を開いている最後のタブを閉じた後、閉じたファイル、条件に一致する全ファイル、または暗号化しないことを選べます。
- **今すぐ保管庫を暗号化してロック**コマンドとリボン操作を提供します。
- ユーザーが選択した場合だけ、現在のプラグインセッション中にパスワードをメモリへキャッシュします。
- リボンのロック下にある赤、緑、黄のランプで、パスワードが利用不可、キャッシュ済み、期限間近の状態を表示します。
- 一定時間後にパスワードだけを消去するか、現在の保管庫で操作がない状態が続いた後に自動的に暗号化してロックできます。
- 既定では `.md`、`.avif`、`.bmp`、`.gif`、`.jpeg`、`.jpg`、`.png`、`.svg`、`.webp` を保護し、除外するファイルやフォルダーも指定できます。
- サブフォルダーを維持し、保管庫の設定フォルダーと `.age` で終わるファイルを除外します。
- 元ファイルを削除する前に、新しい平文または暗号データを再度読み込んで確認します。
- Obsidian のインターフェース言語に従い、英語、簡体字中国語、繁体字中国語、日本語、韓国語に対応します。

## ファイル処理の流れ

`notes/private.md.age` を開いて**復号して開く**を選択すると、次の処理が行われます。

```text
notes/private.md.age
    -> notes/private.md を復号して確認
    -> notes/private.md.age を削除
    -> notes/private.md を標準エディターで開く
```

保護対象の平文を開いている最後のタブを閉じると、暗号化対象の一覧が折りたたまれた状態で表示されます。`.ageconfig` に除外パスがある場合は、スキップするファイルとフォルダーも別の折りたたみ一覧に表示されます。次のいずれかを選択できます。

- **このファイルを暗号化**
- **すべて暗号化（N）**
- **平文のままにする**

Obsidian が通常の保存処理を完了できるよう、タブが先に閉じられます。その後、アプリの実行中に暗号化が行われます。パスワード入力をキャンセルした場合、暗号化中にファイルが変更された場合、または確認に失敗した場合、元の平文ファイルは保持されます。

**すべて暗号化**を選ぶか、**今すぐ保管庫を暗号化してロック**を実行すると、暗号化後にキャッシュされたセッションパスワードが消去されます。次に暗号化ファイルを開くと、パスワードの再入力が必要です。閉じた 1 ファイルだけを暗号化した場合は、セッションパスワードを消去しません。

プラグインは、アプリ終了時のフックを使った対話型暗号化を行いません。Obsidian が非同期処理の完了を確実に待つとは限らないためです。終了前に保護対象のタブを閉じるか、**今すぐ保管庫を暗号化してロック**を実行してください。

## パスワードの動作

- 除外されていない既存の `.age` ファイルがある場合、保管庫全体の暗号化前に入力されたパスワードをそのファイルで確認します。
- `.age` ファイルがない場合は、パスワードを 2 回入力する必要があります。
- 記憶するよう選択したパスワードは、現在のプラグインセッション中だけ JavaScript のメモリに保持されます。
- パスワードが `data.json` に書き込まれることはありません。
- パスワードを復元する方法はありません。紛失すると暗号化ファイルを復号できません。

### セッションのセキュリティタイマー

設定ページには、同時に使用できない 2 つのタイマーがあります。どちらも初期状態ではオフです。

- **パスワードの自動消去**：パスワードがメモリに入った時点から一定時間後にキャッシュを消去します。操作を行っても期限は延長されず、平文ファイルはそのまま残ります。
- **保管庫の操作がないときに自動ロック**：現在の保管庫でキーボード、ポインター、タッチ、スクロール、編集、タブ操作があるたびに計時をやり直します。期限になると、開いている Markdown エディターの保存を待ち、条件に一致して除外されていないすべての平文ファイルを暗号化し、保護に成功したタブを閉じ、確認を追加表示せずにパスワードを消去します。

リボンでは、パスワード自動消去を「鍵＋時計」、自動アイドルロックを「錠＋円形矢印」で表示します。両方のタイマーがオフの場合は通常の錠です。右上のバッジは設定モードを示し、下の赤、緑、黄のランプはパスワードの利用可否と期限が近いことを示します。設定ページでも同じアイコンを使用します。

自動アイドルロックには、パスワードをキャッシュしたままにする必要があります。このモードが有効な場合、パスワード画面の**自動ロックまで記憶する**が常に有効になります。再起動後にパスワードが復元されることはないため、再度入力するまで自動ロックは待機状態になりません。

ここでのアイドルとは、この保管庫の Obsidian メインウィンドウとポップアウトウィンドウで、プラグインが操作を検出していない状態です。OS 全体のアイドル検出ではありません。他のアプリへ切り替えてもカウントダウンは続きます。バックグラウンド同期やファイルの更新日時ではタイマーをリセットしません。コンピューターがスリープするか Obsidian が一時停止した場合、復帰後すぐに期限を確認します。

## 暗号化範囲と `.ageconfig`

ファイル形式は**設定 → Vault in Vault → 保護するファイル形式**で指定します。セキュリティタイマーも同じ設定ページにあります。`.ageconfig` がない場合、拡張子、除外パス、タイマー設定は現在の保管庫にあるプラグインフォルダーの `data.json` に保存されます。パスワードは保存されません。保護ポリシーの編集には保管庫パスワードの確認が必要ですが、タイマーはいつでも変更できます。

Obsidian プラグインと Go コマンドラインツールで同じポリシーを共有する場合は、保管庫のルートに `.ageconfig` を作成します。

```json
{
  "extensions": [".md", ".png", ".jpg"],
  "exclude": ["Public", "Templates/daily.md", "attachments/shared"]
}
```

- `extensions` は保護する平文ファイル形式を指定します。省略すると、Markdown と一般的な画像形式の内蔵既定値を使用します。明示する場合、空の配列にはできません。
- `exclude` には保管庫ルートからの相対ファイルパスまたはフォルダーパスを指定します。フォルダーを指定すると、その配下全体をスキップします。
- パスでは大文字と小文字を区別します。`*`、`?` などのワイルドカード、絶対パス、`..` は使用できません。
- `.ageconfig` がある場合は `data.json` より優先されます。共有された拡張子と除外項目は設定ページに読み取り専用で表示されます。設定ページから OS の既定エディターで開くか、Finder／ファイルマネージャーで表示できます。保存後は **.ageconfig を再読み込み**を選択してください。
- 設定が無効な場合、より広い既定ポリシーへ黙って戻るのではなく、暗号化を停止します。`.ageconfig` と `data.json` のどちらにもパスワードは保存されません。

除外パスだけを設定する場合は、次のように記述できます。

```json
{
  "exclude": ["Public", "Templates"]
}
```

## セキュリティモデル

- ロック解除された内容は、ディスク上の通常の平文ファイルです。
- メタデータキャッシュ、検索インデックス、File Recovery、他のプラグイン、同期ツール、システムバックアップに平文が残る可能性があります。
- クラッシュ、強制終了、停電、アプリの直接終了により平文ファイルが残る可能性があります。
- JavaScript では、パスワード文字列がプロセスメモリから直ちに消去されることを保証できません。
- プラグインは代替ファイルを作成し、読み戻して暗号学的に確認した後にだけ元ファイルを削除します。平文をゴミ箱へ移動すると暗号化されていないコピーが残るため、この切り替えでは Obsidian の通常のゴミ箱機能を使用しません。
- ファイルのロック解除中は、実行中の Obsidian プロセスやローカルファイルを読み取れるソフトウェアまたはユーザーからデータを保護できません。

このプラグインにはテレメトリ、広告、アカウント要件、リモートサービスはなく、現在の保管庫外のファイルへアクセスしません。通常の使用は完全にオフラインです。

## 手動インストール

ローカル開発版をインストールするには Node.js 20 以降が必要です。

```bash
npm ci
npm run check
npm run install:vault -- "/your/vault/の絶対パス"
```

最後のコマンドは `main.js`、`manifest.json`、`styles.css` を次の場所へコピーします。

```text
<Vault>/.obsidian/plugins/vault-in-vault/
```

この 3 ファイルを手動でコピーすることもできます。Obsidian を再起動または再読み込みし、**設定 → コミュニティプラグイン**で **Vault in Vault** を有効にしてください。

以前の開発版を `fileencrypt-age-viewer` という ID でインストールしている場合は、`vault-in-vault` を有効にする前に無効化してください。新しい ID は別のプラグインとして扱われます。拡張子設定を引き継ぐ場合だけ、古いフォルダーの `data.json` を新しいプラグインフォルダーへコピーしてください。パスワードは含まれていません。

## 開発とリリース

```bash
npm ci
npm run dev
npm test
npm run check
```

`npm version patch`、`npm version minor`、`npm version major` のいずれかでバージョンを更新します。スクリプトにより `package.json`、`manifest.json`、`versions.json` が同期されます。manifest のバージョンと完全に一致し、`v` を付けないタグをプッシュすると、GitHub Actions がビルドしてドラフト Release を作成します。別の Release を手動で作成する必要はありません。

ドラフトを開いて release notes を記入し、`main.js`、`manifest.json`、`styles.css` が個別にダウンロードできる 3 つの添付ファイルになっていることを確認してから、**Publish release** を選択します。ドラフトのままでは Obsidian からインストールできず、Community への申請にも使用できません。

## 互換性

Vault in Vault 0.8.0 以降には Obsidian 1.8.7 以降が必要です。これにより、プラグインが Obsidian で選択されたインターフェース言語に従うことができます。
